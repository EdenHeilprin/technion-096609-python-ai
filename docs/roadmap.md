## Institutional-access questions

The course can continue developing while these remain unanswered:

- Is there a funded ChatGPT Education/Codex route for students?
- Is GitHub Copilot available through student/education entitlements?
- Does Technion want the public repository transferred to an institutional organization?
- Does every student have Qualtrics access?
- Is there supported oTree hosting or deployment guidance?

None of these blocks the fundamentals, assessment prototypes, public syllabus, weekly templates, or access-neutral AI teaching routines.

## Decisions to freeze before official publication

1. Confirm whether “two hours” means clock or academic hours.
2. Test the 20/30/40/10 grading model against completed sample tasks.
3. Set the late-work, resubmission, and minimum-individual-evidence rules.
4. Confirm pairs by default or student choice for the capstone.
5. Select the required free/funded AI baseline and outage fallback.
6. Select candidate papers only after both capstone prototypes pass the feasibility test.

## Build order from here

1. Complete this portal, working syllabus, and diagnostic.
2. Prototype Practical Check 1 and the individual demonstration.
3. Build and pilot Weeks 2–4.
4. Prototype the generic DM and OB capstone thin slices.
5. Build debugging, CSV, pandas, and agentic-workflow modules around the evidence those prototypes require.
6. Implement the prepared Moodle structure in a new shell.
7. Rehearse the complete student journey from first visit to final demonstration.
