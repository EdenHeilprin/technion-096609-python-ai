# Working in this teaching project

- Read PROJECT.md and the task's named brief before acting. Ask about a missing scientific decision rather than inventing it.
- Work on the requested milestone only. Preserve source data. Never delete or reset a database containing responses without explicit approval.
- Use the project's Python 3.13 .venv. Do not install packages globally or silently change pinned versions.
- Use clear English # comments in Python explaining unfamiliar lines, concepts, functions, and their purpose. Comment HTML/CSS/JavaScript with their appropriate syntax. Keep comments accurate and concise.
- Do not introduce names, demographics, payments, external analytics, tracking, or new dependencies unless requested.
- Public example data are synthetic. Keep real exports and credentials local and untracked.
- Before declaring success, run relevant code or checks. Distinguish an executed check from one you only recommend. Report changed files, outputs, and remaining uncertainty.
- For parallel work, use separate bounded tasks with explicit file ownership. Do not let two agents edit the same file simultaneously. Return evidence, not just agreement.
- A conversation fork shares history, not necessarily an isolated filesystem. Keep side investigations read-only or use separate output locations/copies for alternatives.
