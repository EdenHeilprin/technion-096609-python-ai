# Trial-level data contract

## Unit of observation

One row represents one participant in one lottery-choice trial, whether completed or timed out.

## Final export fields

| Field | Meaning | Allowed value or rule |
| --- | --- | --- |
| `participant_code` | Anonymous code generated by oTree | Non-empty text |
| `condition` | Participant's feedback condition | `persistent` or `transient`; one value per participant |
| `round_number` | Position of the trial in this participant's sequence | Integer 1–4 |
| `trial_id` | Lottery pair selected from `stimuli.csv` | `T01`, `T02`, `T03`, or `T04`; each once per participant |
| `left_option_id` | Semantic option shown on the left | `A` or `B` |
| `right_option_id` | Semantic option shown on the right | `A` or `B`, and different from `left_option_id` |
| `option_a_low` | Option A low outcome | Integer copied from `stimuli.csv` |
| `option_a_high` | Option A high outcome | Integer copied from `stimuli.csv` |
| `option_a_high_probability` | Probability of Option A high outcome | Number strictly between 0 and 1 |
| `option_b_low` | Option B low outcome | Integer copied from `stimuli.csv` |
| `option_b_high` | Option B high outcome | Integer copied from `stimuli.csv` |
| `option_b_high_probability` | Probability of Option B high outcome | Number strictly between 0 and 1 |
| `sample_sequence_a` | Server-generated available outcomes for Option A | JSON list of five valid A outcomes |
| `sample_sequence_b` | Server-generated available outcomes for Option B | JSON list of five valid B outcomes |
| `sample_count_a` | Number of A outcomes revealed | Integer 0–5; exactly 5 when completed |
| `sample_count_b` | Number of B outcomes revealed | Integer 0–5; exactly 5 when completed |
| `selected_side` | Side selected by the participant | `left` or `right`; blank only after timeout |
| `choice` | Semantic option selected | `A` or `B`, matching the selected side; blank only after timeout |
| `decision_rt_ms` | Time from sampling completion to choice | Non-negative integer when completed; blank after timeout |
| `trial_rt_ms` | Time from decision-page availability to choice | Non-negative integer when completed; blank after timeout |
| `timed_out` | Whether the page timed out | Boolean; `True` or `False` |

## Relationships that must remain true

- Every participant has four rows and one row for each trial ID.
- Every participant has one condition across all four rows.
- Left and right contain A and B exactly once on every row.
- `choice` matches the semantic option on `selected_side`.
- A completed row has counts 5 and 5, a valid side and choice, and both timing values.
- A timed-out row has blank side, choice, and timing values. Partial sample counts are allowed.
- Every value in a stored sample sequence is one of that option's two outcomes.

The final custom export must use exactly the field order shown in the table.
